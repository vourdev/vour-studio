# Project knowledge

Vour Studio — marketing site for an AI-Powered Product Engineering Studio. Next.js 16 (App Router, React Server Components, React Compiler) + TypeScript strict + Tailwind CSS v4. All visitor-facing copy is **Indonesian (id-ID)**; code/comments are English. Auth, admin, and payments are deliberately NOT built — they live in the sibling project `vour-studio-admin` (Payload CMS + Postgres). Single source of truth for devs: `README.md` (very detailed) and `AGENTS.md`.

## Quickstart
- Setup: `npm install` — no env vars needed; everything degrades gracefully (see Gotchas). All env vars are optional and documented in `.env.example` (which exists): `NEXT_PUBLIC_SITE_URL`, `NEXT_PUBLIC_WHATSAPP_NUMBER`, `NEXT_PUBLIC_CONTACT_EMAIL`, `LEAD_API_URL`, `LEAD_API_KEY`.
- Dev: `npm run dev` (Turbopack, http://localhost:3000). **Dev now consumes the PRODUCTION admin** (`https://vour-studio-admin.vercel.app` via `LEAD_API_URL`/`CMS_API_URL` in `.env.local`) — no local admin needed unless you're working on the admin itself.
- Test: none configured (no test runner in repo)
- Typecheck: `npm run typecheck` (`tsc --noEmit`) | Lint: `npm run lint` (ESLint) | Build: `npm run build`
- DB: **none in this repo** — database lives in `vour-studio-admin` (`npm run db:generate` / `db:migrate` there, Payload `migrate:create`/`migrate`).

## Architecture
- `app/` — pages: `/` homepage (composes 10 sections), `solutions|products|projects|about|contact`, `resources` + `resources/[slug]` (blog articles read from the CMS, rendered via Payload's `RichText`), `actions/lead.ts` (contact form server action that forwards leads to the admin CMS API), `sitemap.ts robots.ts not-found.tsx`, `layout.tsx` (fonts, theme, noscript reveal fallback). SEO metadata lives in `lib/seo.ts`.
- `components/` — `layout/` (nav, footer, theme toggle, Lenis provider), `sections/` (one file per homepage section), `motion/` (Reveal, KineticHeading, WaveMatrix, MagneticButton, Marquee, AnimatedNumber), `ui/` (Radix primitives + CVA: button, accordion, field, container), `blog/article-content.tsx` (Lexical body renderer), `forms/lead-form.tsx`, `products/product-browser.tsx`.
- **No MDX anymore** — blog content lives in the CMS Posts collection (Lexical rich text, draft/publish). Article bodies render through `@payloadcms/richtext-lexical`'s `RichText` component into the `.article-prose` styles in `app/globals.css`.
- `lib/` — `site.ts` (brand, nav, CTA labels, contact defaults + `defaultSiteSettings` fallback), `cms.ts` (server-only read path into the admin CMS: `getProducts()` + `getProjects()` + `getPosts()`/`getPost()` + `getSiteSettings()` with ISR + graceful fallback), `seo.ts`, `utils.ts`, `data/` (products, projects, posts, faq, services — many `TODO(Vour)` placeholders; also the fallback data when the CMS is unreachable).
- **No database, email, or admin code here anymore** — all of it moved to the sibling project `vour-studio-admin` (Payload CMS 3 + Next.js 16 + Postgres/Neon, in `/Users/zero/Projects/vour-studio-admin`). Collections there: users, media, posts, products, projects, leads, newsletter-subscribers.
- Data flow: contact form → `app/actions/lead.ts` (zod validation + honeypot) → `POST <LEAD_API_URL>/api/leads` with `x-api-key: LEAD_API_KEY` → admin stores lead + sends Resend email. **Revalidate webhook:** every admin content change fires `POST /api/revalidate` (route handler in `app/api/revalidate/route.ts`) with `x-revalidate-secret: REVALIDATE_SECRET`; it expires the `unstable_cache` entries (tags `cms-products` / `cms-projects` / `cms-posts` / `cms-site-settings` in `lib/cms.ts`) with `revalidateTag(tag, { expire: 0 })` and calls `revalidatePath('/', 'layout')`, so edits go live instantly instead of waiting for the 60s ISR window. The handler then warms every top-level page in the background (`after()` from `next/server` + parallel `fetch`es, `maxDuration = 60`) so the FIRST visitor after an edit gets a fast, fresh page (~0.7s) instead of blocking on regeneration (~4s — the regen cost is several sequential admin fetches). Trade-off: `{ expire: 0 }` is blocking revalidate; without the warm-up, one lucky visitor pays the regen time. Content reads: server components call `getProducts()` / `getProjects()` / `getPosts()` / `getPost()` from `lib/cms.ts` → `GET <CMS_API_URL>/api/products` / `/api/projects` / `/api/posts` (admin REST, public `read: () => true`; posts expose only `_status: 'published'`) via `unstable_cache` (ISR 60s). The cached fetch THROWS on failure so revalidation keeps last-known-good data; the getters only fall back to `lib/data/*` placeholders when nothing good is cached. Client components receive data via props — they never fetch from the CMS. Contact + nav are dynamic too: `app/layout.tsx` calls `getSiteSettings()` (admin Global `site-settings`: contact, socials, mainNav; seeded via `npm run seed:site` in admin) and passes the result to `Nav`/`Footer`; `app/contact/page.tsx` reads it directly. Fallback: `defaultSiteSettings` in `lib/site.ts`.

## Conventions
- Formatting/linting: ESLint 9 + `eslint-config-next`; run `npm run lint` and `npm run typecheck` before finishing.
- **CTA labels are never hardcoded** — import from `lib/site.ts`: `PRIMARY_CTA` "Mulai Project" → `/contact`, `PRODUCTS_CTA` "Lihat Produk" → `/products`, `PROJECTS_CTA` "Lihat Project" → `/projects`, `RESOURCES_CTA` "Lihat Blog" → `/resources` (code wins over the README's "Lihat Tulisan"), `SERVICE_CTA` "Pelajari" → `/solutions#<slug>`. One label per intent, site-wide.
- Technology is never a selling point in visitor copy — only in `/solutions` (technical buyer page).
- Design tokens live in `app/globals.css` (Tailwind v4, NO `tailwind.config.js`; dark mode via `@custom-variant dark`). Locked: one accent cyan `#39d5f6` (README's "acid lime #cde87a" is outdated — the code is authoritative), cool zinc neutrals (never #000/#fff), two radii only (`rounded-surface` 12px panels, `rounded-control` 8px buttons/inputs), Geist Sans + Geist Mono via `next/font` (mono for hero H1s, numbers, labels only).
- Theme: the site is **currently forced dark** — `app/layout.tsx` passes `forcedTheme="dark"` to the ThemeProvider (the in-code comment about "system preference" is stale). The nav `ThemeToggle` (`components/layout/theme-toggle.tsx`) therefore has no visible effect while `forcedTheme` is set; don't "fix" light mode without a design decision.
- Motion: GSAP + Lenis are dynamic-imported (not in initial bundle) and GSAP is restricted strictly to `components/sections/workflow.tsx` (never share a tree with Motion). Every animation collapses under `prefers-reduced-motion`. Scroll reveals use `<Reveal>` (`components/motion/reveal.tsx`) with server-rendered `opacity: 0` + a noscript rule in `app/layout.tsx` so no-JS never shows a blank page.
- Posts gotchas: blog content is Lexical JSON from the CMS — render via `components/blog/article-content.tsx` (`RichText` from `@payloadcms/richtext-lexical/react`) into `.article-prose` CSS in `app/globals.css`. Drafts are invisible to the site (anonymous `read` filters `_status: 'published'`). The article route uses `dynamicParams = true` so newly published posts render on demand with ISR.
- Things to avoid: hardcoded CTA copy, second accent color, decorative dots/markers (accent markers only carry meaning: check icons, workflow nodes), changing locked design tokens (must change everywhere).

## Gotchas
- `app/actions/lead.ts` must always degrade gracefully: no `LEAD_API_URL`/`LEAD_API_KEY` (or admin API down) → log a warning, visitor still sees success. Never error out the user flow. Env vars: `LEAD_API_URL`, `LEAD_API_KEY` (see `.env.example`).
- `lib/cms.ts` must also degrade gracefully: CMS unreachable → `getProducts()` / `getProjects()` return the static placeholder data and log a warning; never throw in the render path. Env: `CMS_API_URL` (defaults to `LEAD_API_URL`, then `http://localhost:3000`). Media URLs relative to the admin (local dev) are absolutized against the CMS origin; `next.config.ts` `images.remotePatterns` allows `localhost` + `*.r2.dev` + the R2 custom domain `media.vour.studio`.
- `SelectedProjects` renders exactly 3 rows from the CMS list (2 zigzag + 1 full-bleed); it guards against fewer than 3 projects (zigzag only for available ones, full-bleed only when a 3rd exists).
- **Port conflict:** both this repo and `vour-studio-admin` default to port 3000. Since dev now points at the **production admin**, the local admin normally isn't running — no conflict. If you run the admin locally for admin-side work, give one a different port (`npm run dev -- -p 3001`) and point `CMS_API_URL`/`LEAD_API_URL` at `http://localhost:3000`.
- **Revalidate secret must match everywhere** (added Aug 2026): marketing `.env` + marketing Vercel project + admin Vercel project (`REVALIDATE_SECRET`), plus `REVALIDATE_URL` on the admin (= marketing site URL, `https://https://vour.dev`). Mismatch = 401 from `/api/revalidate` (webhook silently fails, site falls back to 60s ISR). Unset = endpoint refuses 401 and hooks are no-ops. `REVALIDATE_SECRET` lives in the gitignored `.env` files + both Vercel projects (never committed); `.env.example` keeps a blank placeholder. Gotcha: appending to `.env` without a trailing newline glues lines together — `grep '^KEY='` then silently returns the wrong value.
- **Production admin is the default CMS origin.** `.env.local` and `.env.example` set `LEAD_API_URL` + `CMS_API_URL` to `https://vour-studio-admin.vercel.app` (dev too). Env changes need a dev-server restart to take effect. Verified (Aug 2026): products/projects/posts/media/site-settings all read from production; media URLs are already absolute R2 URLs and pass through `next/image` untouched.
- **Vercel project env vars must exist in the dashboard too** (`.env.local` is gitignored and never reaches Vercel). Aug 2026: the marketing Vercel project was missing `LEAD_API_URL`/`CMS_API_URL` — production silently served `lib/data/*` fallbacks for weeks (picsum images, nav "Blog" instead of CMS "Resources"). Fixed by adding all three (`LEAD_API_URL`, `CMS_API_URL`, `LEAD_API_KEY`) to the Vercel project (Production envs) + `vercel --prod`. Symptoms to look for: picsum URLs and fallback copy in production HTML. Note: deploy via CLI only (project not connected to git); after deploys, pages may serve stale ISR/edge-cached HTML for a few minutes — a cache-buster query (`/?_=x`) forces a fresh render. If content edits don't appear, redeploy rather than debugging code. The admin side reads from R2's free bucket URL (`pub-d019cf0de3b6493dae54dd0f42f7efd8.r2.dev`), and `next.config.ts` `images.remotePatterns` already allows it.
- **Leads key must match the admin's Vercel env.** `app/actions/lead.ts` POSTs to `<LEAD_API_URL>/api/leads` with `x-api-key: LEAD_API_KEY`. A mismatch returns 401 (missing key returns 503) and the lead is silently dropped (visitor still sees success). The key lives in THREE places that must be identical: marketing `.env`/`.env.local` (`LEAD_API_KEY`), the marketing Vercel project env (redeploy needed after changing), and the admin's Vercel project env. Synced Aug 2026 (64-char key in all local `.env*` files + both Vercel projects) and verified: `POST /api/leads` → 201. If leads stop arriving, `curl -X POST <LEAD_API_URL>/api/leads -H 'x-api-key: <key>' -d '{"name":"x","email":"a@b.c","message":"test minimal 20 karakter"}'` and check the status (401 = key mismatch, 503 = key unset on admin).
- **R2 media: no custom domain yet.** `vour.studio` is NOT registered/owned, so the `media.vour.studio` custom-domain plan is on hold. Media is served from the free per-bucket URL `https://pub-d019cf0de3b6493dae54dd0f42f7efd8.r2.dev` (admin's `R2_PUBLIC_URL`). The `media.vour.studio` entry in `next.config.ts` `remotePatterns` is a harmless placeholder for the future — remove it if it stays unused.
- **Local DNS blocks `*.r2.dev` (internetpositif / Trust Positif).** This dev machine's network hijacks plaintext DNS — even `dig @1.1.1.1` answers `internetpositif.id` (36.86.63.185), whose expired TLS cert breaks R2 image loading in local dev (`SSL certificate problem: certificate has expired`). Fix: enable **DNS over HTTPS** in macOS (System Settings → Network → Wi-Fi → Details… → DNS → "DNS over HTTPS"). Production is unaffected: `next/image` fetches server-side on Vercel and browsers only hit Vercel's `/next/image` proxy, never r2.dev directly.
- **`npm run seed:media` (admin) must run with R2 fully configured** (all five `R2_*` vars set, which activates `@payloadcms/storage-s3`). If it runs with the plugin inactive, files land in the admin's local `media/` folder but media docs get R2-style URLs while the bucket stays empty → every product/project image 404s on the site. Fix: delete the broken media docs, then re-run `npm run seed:media` (uploads real files via Payload). This happened in Aug 2026 and was fixed; images are now real branded Vour placeholders served from R2.
- **Dev servers started from an automation shell die when that shell exits** (process-group cleanup kills even `nohup`). For persistent local dev, run both servers in tmux: `tmux new-session -d -s vour-admin 'cd ~/Projects/vour-studio-admin && npm run dev'` and `tmux new-session -d -s vour-site 'cd ~/Projects/vour-studio && npm run dev -- -p 3001'`. Attach with `tmux attach -t <name>`, stop with `tmux kill-session -t <name>`.
- **`unstable_cache` is sticky in local dev.** After editing CMS content (especially the `site-settings` global) the marketing dev server can keep serving cached values — restart it (`rm -rf .next` in `vour-studio` if it persists) to pick up changes. In production ISR revalidates every 60s, so deploys pick up admin edits automatically.
- Admin products/posts are seeded via scripts in the sibling repo (`npm run seed:products` there; pattern from `scripts/create-admin.ts`).
- **Lexical listitem JSON MUST have numeric `indent`** or the admin editor crashes with `Minified Lexical error #117` ('Invalid indent value.') when opening the post: `@lexical/list`'s `ListItemNode.setIndent` throws on any non-number (`ElementNode.updateFromJSON` calls `setIndent(serializedNode.indent)` unguarded). The seed script's `listItem()` helper used to omit the key — seeded posts with lists broke the admin editor on open. Fixed Aug 2026: helper now sets `indent: 0`, and `npm run fix:listitem-indent` (admin `scripts/fix-listitem-indent.ts`, idempotent, walks published + draft content) repairs existing posts. Never build Lexical listitem nodes without a numeric `indent`.
- **Admin Users password override MUST stay `virtual: true`** (admin `src/collections/Users.ts`). Payload auth stores passwords as `salt`+`hash` — there is NO `password` column in the DB. In Aug 2026 a custom field named `password` (eye show/hide toggle, `src/components/fields/PasswordInput.tsx`) was added WITHOUT `virtual: true`; the persisted field made every users query `SELECT users.password`, which broke production login (`column users.password does not exist`) until the fix. Rules: keep `virtual: true` + `admin.readOnly: false` (Payload defaults virtual fields to read-only), do NOT add `required: true` (would leak into the REST JSON schema on updates; the hidden built-in auth block enforces required-on-create for free), and the component hides Payload's duplicate built-in password block via a `<style>` targeting internal classes (`.collection-edit__auth .auth-fields__changing-password`, `#change-password`) — re-check those class names on Payload upgrades.
- Admin project is a sibling repo at `/Users/zero/Projects/vour-studio-admin` with its own env: `DATABASE_URI` (Neon pooled), `PAYLOAD_SECRET`, `LEAD_API_KEY` (must match marketing site), optional `RESEND_API_KEY`/`RESEND_FROM`/`LEAD_NOTIFICATION_EMAIL`.
- Next 16 has breaking changes vs training data — read `node_modules/next/dist/docs/` before writing Next code (see AGENTS.md).
- `docs/PRD.md` and root `PRD.md` are out of date on infrastructure (say Supabase/Prisma/Docker/VPS; actual stack is Vercel + sibling admin CMS `vour-studio-admin` with Payload/Postgres).
